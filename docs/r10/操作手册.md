# R10 操作手册

## 架构与边界

一套 `longyun-agent` Compose 项目共享 Keycloak、API、前端、PostgreSQL、MinIO。控制面作为内网 sidecar，仅提供 `/healthz`、`/status`，不经公网网关发布。机构配置表为每个机构登记独立 Bucket 与业务数据库；当前生产业务机构是 `hainan-nanfan`。AI 网关任务表中的 `institution_id` 就是队列命名空间，控制面按此字段列出等待、运行和暂停数量；全局并行槽仍为 4。控制面不读取消息正文，也不返回密钥。

## 部署 / 检查

在受控的发布目录中运行，沿用已经审核过的 LAN、ACPs 与镜像覆盖文件，并把 R10 文件加在最后。下面的命令以当前生产发布目录为例，执行前确认目录与镜像标签：

```bash
cd /home/lijian/releases/longyun-agent-acps-operator-20260918-r1
export CONTROL_PLANE_IMAGE="$(docker inspect longyun-agent-api-1 --format '{{.Config.Image}}')"
bash deploy/compose.sh --env-file deploy/.env.production \
  -f docker-compose.lan.yml \
  -f deploy/acps/docker-compose.acps.yml \
  -f deploy/acps/docker-compose.release.yml \
  -f deploy/r10/docker-compose.r10.yml \
  -p longyun-agent config -q
bash deploy/compose.sh --env-file deploy/.env.production \
  -f docker-compose.lan.yml \
  -f deploy/acps/docker-compose.acps.yml \
  -f deploy/acps/docker-compose.release.yml \
  -f deploy/r10/docker-compose.r10.yml \
  -p longyun-agent up -d --no-deps control-plane
docker exec longyun-agent-control-plane-1 python /opt/longyun-r10/control_plane.py check
```

`control-plane` 使用同一台服务器本地已有 API 镜像，未重新拉取基础镜像，也不触碰其它 Compose 项目。服务的内部 `/status` 可通过 `docker exec` 或 Docker 网络访问，不向普通业务账号开放。生产运行时的实际目录、镜像、容器状态与命令结果应记录在测试报告。

## 存储策略与队列命名空间

每个机构的 Bucket 默认无匿名 S3 Bucket Policy；`reconcile` 只针对 `institution_data_config` 中处于 active 的 Bucket，撤销可能遗留的匿名策略，并将变更写到 `longyun-agent_r10_audit` 卷中的 `control-plane.jsonl`。执行前检查维护窗口，执行后检查状态：

```bash
docker exec longyun-agent-control-plane-1 python /opt/longyun-r10/control_plane.py reconcile
docker exec longyun-agent-control-plane-1 python /opt/longyun-r10/control_plane.py check
```

不能把 MinIO 根密钥或跨机构对象路径发给业务用户。对队列按机构分组的检查在控制面状态输出的 `queue_namespaces` 中；系统目前是单机构，因此预期只出现 `hainan-nanfan`，若以后增加机构须重新进行隔离测试。当前队列门限只在单个 API 进程内生效；在完成分布式队列改造之前，不应横向启动多个 API 副本。

## 备份与审计

在暂停导入、上传及文档解析的维护窗口执行：

```bash
bash deploy/backup.sh deploy/.env.production
bash deploy/r10/verify-backup.sh /home/lijian/releases/<发布目录>/deploy/backups/<时间戳>
bash deploy/r10/destroy.sh --env-file deploy/.env.production
bash deploy/r10/rollback.sh --env-file deploy/.env.production
```

备份包括所有非模板 PostgreSQL 业务库、角色/授权元数据、MinIO/原始文件/研究文件/ACPs 状态及配置。模型缓存可重新获取，不作业务备份。备份目录含密码与证书，权限为仅属主读取，必须复制到加密且访问受限的异机介质。销毁脚本默认仅展示目标；真正销毁需匹配项目名的确认令牌、已验证备份以及额外生产参数，不得在验收时执行。`deploy/r10-audit.jsonl` 与备份 `MANIFEST.txt`/`SHA256SUMS` 可用于审计。

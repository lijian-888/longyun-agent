# R10 回滚方案

## 触发条件

控制面不健康、存储策略核查误报、或新增编排导致现有共享服务异常。R10 没有修改业务表结构与 API/前端镜像；优先回滚新增 sidecar，保留共享服务及数据卷。

## 操作

1. 记录 `docker ps`、`docker inspect longyun-agent-api-1` 的镜像标签及最近备份路径；检查备份：`bash deploy/r10/verify-backup.sh <备份目录>`。
2. 先运行 `bash deploy/r10/rollback.sh --env-file deploy/.env.production` 核对目标。
3. 执行 `bash deploy/r10/rollback.sh --env-file deploy/.env.production --execute --confirm ROLLBACK:longyun-agent`。它只停止并删除 `control-plane` 容器，不移除数据库、MinIO 或审计卷。
4. 验证 `https://longyun.e-farmer.cn/`、`/api/health` 和 Keycloak OIDC 元数据。确认其他业务容器仍健康。
5. 修复后按操作手册中的 `up -d --no-deps control-plane` 恢复，重新运行 `check`。

若发生业务数据损坏，先停止写入，再用已验证备份在**隔离环境**测试 `pg_restore` 与对象卷解包，确认完整后通过变更审批恢复生产；不得直接在运行中的业务库执行覆盖式还原。备份中的 `release-config.tar.gz` 含证书与密钥，恢复操作必须由有权限的运维人员执行。演练结论与时间记录在 [测试报告.md](测试报告.md)。

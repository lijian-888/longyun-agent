# 海南南繁单机构与课题权限实现说明

## 运行边界

- 平台机构固定为 `hainan-nanfan / HNNF / 海南南繁`，由服务端常量提供。
- 前端、Token 和业务请求均不接收机构编号；不存在机构开通、选择、切换或按机构分配资源的入口。
- 历史业务数据在启动迁移时自动归入默认课题 `HNNF-DEFAULT / 海南南繁水稻育种研究`。
- 试验地点、品种来源单位或审定标准中出现的其他省份属于科研来源和证据信息，不代表平台机构或租户。

## 三类角色

| 角色 | 主要能力 | 课题范围 |
| --- | --- | --- |
| 数据处理员 | 导入、解析、质检、审核、发布、基因型治理申请处理 | 所有活跃课题 |
| 字段管理员 | 课题成员、应用账号状态、模板、规则、公共知识和权限审计 | 所有活跃课题 |
| 科研人员 | 已发布数据查询、私人会话/附件/知识、GWAS、基因型资产和结果库 | 仅已加入课题 |

Keycloak 仅配置这三种业务角色。一个账号若同时持有多种业务角色，API 会拒绝访问并要求身份管理员修正，避免叠加权限导致越权。

## 数据和文件归属

以下数据均具有非空 `project_id`，请求由 `X-Project-Id` 选择课题；科研人员选择未加入课题时返回 403：

- 品种、来源审核、常规表型、根系表型和字段变更申请；
- 区域试验导入批次、发布资料包和田间试验；
- 私人会话、消息、附件、审计、结果文件和 PDF 报告；
- 私人/公共知识文件夹、文档与向量切片；
- GWAS 计划、基因型资产、版本、上传、处理任务、样本映射与治理申请；
- 模拟育种档案项目。

原始导入文件、区域试验资料包、知识文件、会话附件和结果产物按课题目录保存；私人数据在课题边界之上继续按 Keycloak `sub` 隔离。数据库、Docker 卷和任务执行器仍各使用一套海南南繁环境，没有按机构复制基础设施。

## 数据库强制隔离

- 私人会话、消息、附件、审计和成果使用 PostgreSQL RLS，同时校验 `app.project_id` 与 `app.research_user_id`。
- 私人知识使用相同的课题/账号双重 RLS；公共知识仅在当前课题内可见，发布和撤回仅允许字段管理员。
- GWAS 和基因型资产同样使用课题/账号 RLS；数据处理员只能看到当前课题的基因型治理摘要，不能读取原始文件、路径或哈希。
- API 的 ORM 查询和新增记录统一应用活动课题过滤/自动赋值，原始 SQL 接口显式携带课题条件。

## 账号与审计

- Keycloak 负责账号、密码、登录和唯一业务角色；应用不复制密码系统。
- 应用维护 Keycloak 身份映射、海南南繁应用启停状态、科研人员课题成员关系。
- 课题创建/修改、成员添加/修改/移除、账号启用/停用写入 `permission_audit`。
- Keycloak realm 开启登录事件、管理员事件和管理员事件详情，旧 `institution-id` 协议映射已删除。

## 验收命令

```powershell
python -m py_compile backend/app/*.py
cd frontend
npm run build
cd ..
$testsPath = (Resolve-Path 'backend/tests').Path
docker run --rm -v "${testsPath}:/app/tests:ro" longyun-main-rework-api python -m unittest discover -s /app/tests -v
docker compose -p longyun-main-rework ps
```

`backend/tests/test_project_access.py` 覆盖科研人员仅可见已加入课题、未授权课题返回 403、数据处理员岗位范围和权限审计。部署验收还应分别使用三类正式账号登录，验证其菜单，并用两个科研账号确认私人会话互不可见。

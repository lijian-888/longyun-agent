# v1.4.2：科研助手真实流式输出

## 本次调整

此前农业科研助手虽然向浏览器分段发送文字，但实际流程是先等待模型完整回答，再按固定长度切分发送。因此用户在“正在调用大模型”阶段看不到真实生成进度。

本版本改为直接消费模型服务的 SSE 流，并将 AgentScope 接收到的增量文本立即转发到浏览器。图片分析也改为直接转发多模态模型的原生流式结果。

## 保留的安全机制

1. 受控 ReAct 的证据读取步骤保持不变：先读取已发布数据、当前会话附件、知识库命中片段，必要时再读取已准备的可信公开参考。
2. 流式回答保留首段与末段短暂缓冲；每次增量都会检查 `<think>`、`<tool>`、函数调用文本和“准备搜索”等内部协议泄漏。
3. 在任何文本尚未展示时发现协议泄漏，系统会自动丢弃该次输出并重试一次；已经展示后发现异常，则立即停止，避免把异常内容保存为正式科研结论。
4. 完整答案在写入 PostgreSQL 会话记录前仍会做最终校验和展示清理，移除无语义的 Markdown 分隔线。

## 用户可见变化

1. 助手开始产生可展示文本时，页面状态从“正在调用大模型”更新为“正在接收大模型回答”。
2. 回答会随着模型实际返回的增量持续出现，不再等待整段回答完成后一次性出现。
3. 对于采用长推理模式、先生成隐藏 reasoning 再输出正文的模型，页面仍不会展示推理内容；可见正文一旦到达即开始流式显示。

## 验证

1. 使用当前模型配置直接调用 OpenAI 兼容 `/chat/completions`，确认服务返回多条 SSE 增量事件。
2. 使用 AgentScope 受控 ReAct 路径验证，确认浏览器消费的 `token` 事件来自模型消息队列，而非后端按固定长度伪造切片。
3. 使用包含 `</think><tool>` 的模拟输出验证，确认安全缓冲会拦截并阻止该文本进入最终答案。

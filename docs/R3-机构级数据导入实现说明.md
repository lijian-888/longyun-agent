# R3 机构级数据导入实现说明

## 1. 实现范围

系统保留“登录后自动进入所属机构”的使用方式，不向普通用户提供机构选择或跨机构切换。
平台目录中的每个机构具有独立的数据平面：

- 私有 MinIO Bucket：`longyun-<机构代码>`；
- 独立 PostgreSQL 业务数据库：`longyun_<机构代码>`；
- 应用访问策略同时校验登录账号 `institution_id` 与当前 `project_id`；
- 所有结构化实体、关系、问题和批次仍显式保存 `institution_id`、`project_id` 与实体标识。

控制数据库只保存机构到 Bucket/数据库的路由和非敏感访问策略，不保存 MinIO 密码。
MinIO Bucket 默认为非匿名私有 Bucket；服务端使用受控凭据访问，浏览器不能直接取得对象路径。

## 2. 支持的数据与格式

| 数据类型 | 格式 | 主要实体标识 |
| --- | --- | --- |
| 种质资源 | CSV、XLSX、JSON | `germplasm_id` |
| 系谱 | CSV、XLSX、JSON | `child_id`、双亲材料标识 |
| 试验/表型 | CSV、XLSX、JSON | `observation_id` 或稳定派生标识、`germplasm_id` |
| 环境 | CSV、XLSX、JSON | `environment_id` |
| 基因型 | VCF、VCF.GZ、PLINK ZIP | 数据集哈希、样本 IID |
| 公开文献 | PDF、DOCX、TXT | 文件 SHA-256 |

数据处理员可以直接使用标准列名，也可以提交 JSON 字段映射。映射方向固定为：

```json
{
  "原材料号": "germplasm_id",
  "名称": "name"
}
```

已有六套结构化模板可通过 `template_version_id` 绑定到导入批次；导入记录会保存模板版本和
字段映射快照，后续不会因模板更新而失去可追溯性。

## 3. 文件大小与传输

- 常规单文件：不超过 200MB；
- VCF.GZ 和 PLINK ZIP：不超过 2GB；
- 未压缩 VCF：按常规单文件 200MB 限制；
- API 按 8MB 分块流式接收并实时计算 SHA-256，超过上限立即终止，不把大文件整体读入内存；
- 临时文件只用于校验和写入 MinIO，完成或失败后都会清理；
- MinIO 写入成功、结构化处理失败时保留原始对象，并返回“原始文件已保存，可修复后重新处理”的提示。

## 4. 关联与问题提示

机构业务数据库包含：

- `ingest_batch`：原始对象、文件哈希、模板版本、映射和处理状态；
- `data_entity`：按机构、课题、实体类型和实体标识保存结构化数据；
- `data_relation`：系谱、表型—材料、表型—环境、基因型样本—材料等关联；
- `data_issue`：缺失数据、关联异常、严重程度及受影响功能。

示例提示：

- “第 3 行缺少必填字段：germplasm_id、value”；
- “基因型样本 X 未关联到同编号种质材料”；
- “表型记录无法关联 environment:Y”；
- 受影响功能会同时列出，例如“性状查询、区域试验分析、GWAS”。

追溯接口严格限定当前账号机构和当前课题：

```text
GET /api/institution-data/trace/{entity_key}
```

## 5. 主要接口

```text
GET  /api/institution-data/contracts
GET  /api/institution-data/config
POST /api/institution-data/imports
GET  /api/institution-data/imports
GET  /api/institution-data/trace/{entity_key}
```

`POST /imports` 使用 `multipart/form-data`：

- `dataset_type`：六类数据之一；
- `file`：上传文件；
- `template_version_id`：可选的已发布标准模板版本；
- `field_mapping`：可选 JSON 对象。

## 6. 部署配置

生产 `.env` 至少需要：

```dotenv
INSTITUTION_DATA_ENABLED=true
MINIO_ROOT_USER=<服务端专用账号>
MINIO_ROOT_PASSWORD=<独立强密码>
```

MinIO 仅位于 Docker 内部网络，不通过生产网关公开。API 使用迁移账号创建机构数据库，数据库
Owner 为最小权限应用角色 `rice_app`。新增机构应通过受控运维流程写入 `institution` 目录，
重启 API 后会自动配置其 Bucket、访问策略和业务数据库；普通用户不能自行开通机构。

## 7. 演示与验收

完整六类演示数据位于 `samples/institution-demo`，按 README 顺序导入。自动测试：

```powershell
cd backend
python -m unittest tests.test_institution_data -v
```

验收还应在 Docker 环境中确认：MinIO 对象数、机构数据库批次数、实体/关系/问题数、
`HNNF-G001` 追溯结果，以及超限文件和缺失关联样例的明确错误信息。
